## 接手顺序

直接转交给同事请先看 [接手手册](docs/TAKEOVER_MANUAL.md)，其中第 6 节是可由同事本人发送给自己 dot 的接手任务模板。仓库和现有 18 个普通原件包已按所有者确认公开，读取、克隆和下载无需邀请；写入、合并与部署仍须授权。

这个仓库包含资料集合、已部署网站的运行代码和继续维护的方法说明。先完成下面四步，再开始补资料或部署：

1. 看 [项目概览](docs/PROJECT_OVERVIEW.md)，确认已做工作、数量口径与未完成边界。
2. 进入 [网站目录](website/README.md)，按 [启动与部署说明](docs/WEBSITE_OPERATIONS.md) 在自己的授权环境运行；源码与原站点的对应关系见 [来源说明](docs/WEBSITE_PROVENANCE.md)。
3. 从 [公开 Release](https://github.com/hui-li-312/insurance-materials-handover/releases/tag/v2026.10.27) 取得 18 个普通原件包，按 [恢复说明](docs/RESTORE.md) 验证并恢复 4,662 份资料。Git 克隆本身不包含这些大文件。
4. 按 [采集核验方法](docs/METHODOLOGY.md)、[待办清单](docs/BACKLOG.md) 和 [贡献规则](CONTRIBUTING.md) 选一个小任务，在测试分支完成采集、核验、更新和验收。

研究目录与网站展示数据是不同投影；没有验证过的数据转换流程时，不要假定修改 JSONL 就会自动更新网站。当前没有承诺一键全市场爬取、自动法律审核或现成定时采集服务。运行和部署权限也不会随着仓库链接自动转移。

## 从哪里开始

1. 阅读 `docs/HANDOVER.md`，了解范围、遗留缺口与接手验收。
2. 在 `catalog/materials.csv` 中按地区、公司、产品筛选；需要完整结构时读 `catalog/{地区代码}.jsonl`。
3. 最新台账在 `deliverables/保险条款采集首批交付台账.xlsx`，先看“交付范围与后续采集”工作表。
4. 原件以公开 Release 附件交付，不把多 GB 二进制资料写入 Git 历史。下载并校验清单列出的附件后，按 `docs/RESTORE.md` 恢复。
