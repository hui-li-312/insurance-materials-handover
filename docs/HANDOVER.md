# 交接说明

## 本轮冻结范围与遗留事项

本轮 138 份目标材料中，127 份全文审读、3 份部分核验、8 份未完成全文审读。8 份包括 7 份说明材料缺对应主合同，以及 1 份身份／高棉语核验未完成材料。另有 4 份马来西亚文件已全文阅读，但产品身份对应仍受保留；不得将其标为核验通过。这些是本轮范围，不是整个资料库的未完成总数。

待补资料优先按发行机构官网、监管披露、银行／已授权中介销售页核对。必须匹配产品正式名称、发行实体、版本、渠道、地区和条款代码，不能用同名册子或相近产品替代主合同。旧条款、宣传册、CIS、附约与主文分别建档。

已准备但未发送的官方索取邮件仍待另行授权；此仓库的创建不代表任何邮件已经发送，也不授予同事使用原用户邮箱的权限。不要从交接文件推断账号访问许可。

## 状态定义

- `is_primary`：文件角色标记，不能单独推出全文核验通过。
- `content_review.all_pages_reviewed` / `full_content_review_complete`：全页阅读完成，不等于无歧义、身份已对应、现售采用或完整签发合同包。
- `content_review.status=verified`：文件内容层的核验结果，只有同时满足主文角色和相应严格条件的子集才计入“严格核验主文”。不能直接把所有 verified 条数当作 426。
- `needs_review`：存在待核问题；可能已经读完，也可能未完成。结合全页标记与身份边界看。
- `partial`：状态标签不等于汇总的所有部分审读记录，部分阅读也可能保留其他状态。
- `quarantined_from_public`：隔离保留，不进入公开目录；不自动等同违法或保密认定。
- `raw_file_transfer_status`：本次 GitHub 交接的文件恢复状态，不替代原始审读结论。
- `null`、字段缺失和 `false` 不互换；未知日期保持未知。

## 维护规则

新增材料先记录官网页面与下载地址、采集时间、来源发布日期、事件／生效日期，再保存原字节和 SHA-256。按 SHA 去重，按实体／产品／版本／渠道维护关系，绝不因为名称相同就覆盖旧文件。保留不可访问、受限和未确认状态，不绕过登录、下载限制或验证码。

发现错误用可追溯更正，不悄悄改写旧版原件或历史核验结论。重大条款判定需记录页码和证据；不得把厂商宣传、模型摘要当合同主文。

## 接手验收

1. 随机选一个地区和产品，通过索引找到原件并验证哈希。
2. 找出一个待核事项，说清原因和下一条合法获取路径。
3. 在测试分支增加一条材料记录，验证没有覆盖旧原件或丢失历史。
4. 分别检查普通原件与隔离记录数量（51 份隔离原件暂不随仓库交付）；确认无需邀请即可读取公开仓库并下载普通 Release 附件。
5. 不交接个人账号密码；仓库写入、合并与部署权限由所有者指定并单独授权。

## 历史台账的可访问性与版本

台账按第 11 版原字节保留。旧概览、旧批次页面的版本号属于当时快照，不是最新状态；“交付范围与后续采集”页的 index103／Site127 才是当前交接基线。台账含原账号私有归档下载链接及历史证据相对路径，不能保证同事可访问，不应把这些链接当作已完成权限交接。底层普通原件一律使用本项目清单及公开 Release 恢复路径；历史私有归档不会因此开放。

公开目录有 2360 个目录项及 4760 个材料项，不等于 2360 个已独立核实产品，也不等于 4713 个原件；目录可能保留未完全归一的来源标签组。

`associations` 与 `source_associations` 保留同一原件的多产品／渠道／版本来源标签，仅用于追溯关系，不从历史来源标签继承“已核验”结论。当前文件状态以记录本身的 `content_review` 等字段为准。
