# 接手后的优先任务

以下是已知缺口与建议处理顺序，不是对各地区全部缺口的穷举。先沿现有 `catalog` 记录和台账查证，再开新任务；不要为了增加数量重复下载同一 SHA。

## 首次接手验收

- 确认无需邀请即可读取公开仓库、克隆代码并下载现有普通 Release 附件，而不是仅能打开目录网站；后续写入和部署仍须授权。
- 按 [恢复说明](RESTORE.md) 恢复 4,662 份普通原件，核验包大小、SHA 和单文件清单；51 份隔离记录应保持不可恢复到普通目录。
- 按 [网站操作说明](WEBSITE_OPERATIONS.md) 启动网站，抽查一个地区、一个产品和一组材料链接。
- 找到一个 `needs_review` 或部分审读记录，确认能看到问题、页码、来源与适用限制。
- 在测试分支完成一次小改动和回退，不直接改生产站点。

## P0 保持安全边界和口径

1. 51 份隔离原件不上传到普通 Release、不进入公开页面或自动问答。解除隔离需要逐项完成来源、隐私和适用性复核并获得相应授权，不能仅凭 SHA 一致。
2. 维护统计单位：原件、网站目录项、材料关联、主文角色、全文审读、严格通过分别计算。最新汇总依赖 manifest 与实际记录，不从旧台账概览抄数。
3. 确认网站展示数据与研究目录的更新路径。它们是不同数据投影，不能假定更新 JSONL 会自动更新公开网站。

## P1 马来西亚主合同和身份对应

### 最近一轮的七份支持材料

已有说明或证书类材料尚未形成可确认的对应主合同关系。继续查发行人下载中心、明确的银行销售页和正式主合同／附约，核对持有人、渠道、计划和代码。不要求“找到任何同代码文件”，而是证明它就是该支持材料引用的合同。

线索包括 `GTTCP0425`、`GTTCIMB0623`、`GTLCIMB1124`、`GTTSA0425`、`GTTCIMB1024`。部分代码在其他主合同或候选记录中已经出现，不能据此宣称七个缺口全部已补；这些线索也不是七份材料的逐一等价清单。以台账“交付范围与后续采集”及逐条来源为任务入口。

建议验收证据：发行人或对应银行的正式引用关系、同一持有人／版本／计划、完整主文及明确引用的通用附约。仍无证据时保留支持材料，不增加主文或产品补齐计数。

## P1 柬埔寨语言与版本证据

最近一轮仍有一份身份／高棉语核验未完成的材料；另有部分审读记录。由能可靠处理相关法律语言的复核者逐条校对，不用已读英文页替代高棉语正文。

可直接着手的部分审读例子：

- `04b8a27f379c…` Traveller’s Insurance：英文物理页 13–25 已读，高棉语页 1–12 及双语等价性仍需核验。
- `3e77306f9911…` EASYCare：32 页均有可视内容，页 2–31 的高棉语法律语义仍未可靠核验。
- `5afad175725a…` Personal Accident and International Emergency Medical Assistance：高棉语页 1–20 待核；英文主文与附约的交叉引用及儿童最低年龄表述也需保留并核对。

这些是当前索引例子，不把它们擅自合并成最近一轮“身份保留的那一份”。验收同时包括语义、产品身份、版本、附表／附约关系，不只统计看过页数。

## P1 中国香港官方索取

已准备但未发送的索取方向包括 Trinity Private Motor Car、TripCover、Manulife Harvest Saver 的 DBS 两年缴费三年期满版本、HSBC Life GoalAccess Universal Life 的 Education 版本。

需要的是公开标准主条款、必要附约、空白通用附表及版本适用说明，不是客户签发保单。Harvest Saver 整付版本不能替代 DBS 两年缴版本；GoalAccess Protection 不能替代 Education。先复查官网／对应销售渠道是否已经公开，再在明确授权收件机构和内容后发出索取请求。不要使用原维护人的邮箱权限作为默认交接资产。

## P2 其余地区的计划性补充

SG、TH、ID、PH、VN、BN、LA、MM 及其他未闭合记录，先从各自 JSONL 的 `gaps`、`content_review`、身份／版本限制和来源关联生成待办。没有逐条证据时，不给整个地区下“条款已完整”或“无条款公开”的结论。

每个地区下一轮先做一小批高优先产品：有明确需求、可找到官方主文、版本关系可证、尚未重复收录。记录选样依据与排除理由，再决定是否扩大覆盖。对受限官方站点保留失败记录，不把换域名或重复请求当作补缺计划。

## P2 工程化建议

这些是待做项，不是仓库已经实现的能力：

- 将手工记录的来源检查整理为可重复的采集任务清单，增加速率控制、失败分类与同源访问停止条件。
- 增加稳定的数据 schema 与校验工具，但先兼容现有多类型字段、`null` 和历史含义，不为整齐而删掉限制说明。
- 为“研究目录 → 网站展示数据”增加明确、可测试的投影构建流程；没有证据的产品归一不要自动化。
- 对重要条款更正建立双人复核及回归样例，重点覆盖双语、公式、版本／渠道混淆。
- 只有经授权后再配置 CI、定时采集或自动部署；不要为了方便创建新密钥或扩大账户权限。

## 每项任务的关闭条件

关闭时记录目标、原件 SHA、来源、日期、实际改变、复核结果、仍然存在的限制，以及对应 Git 提交／Release。找到一个文件不等于补齐整个产品；允许以“证据不足，保留待核”结束本轮检查，但不能把该缺口标成已解决。
