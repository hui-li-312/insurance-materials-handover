# 保险目录补采与离线 QA 协议

本协议补充 [METHODOLOGY.md](METHODOLOGY.md)、[TAKEOVER_MANUAL.md](TAKEOVER_MANUAL.md) 和 [CONTRIBUTING.md](../CONTRIBUTING.md)，用于接手人做一个**边界明确、证据可追溯的小批次**。网站启动、构建与部署仍按 [WEBSITE_OPERATIONS.md](WEBSITE_OPERATIONS.md)，本协议不改变既有原件、目录、隔离或发布状态。

配套 Python 工具只做 **OFFLINE triage（离线初筛）**：校验有限 URL 清单、分析已经合法取得的缓存文本、计算文件哈希、运行合成测试。它不是自主爬虫、不是绕过工具、不是通用授权或隐私／法律通过证明；没有 HTTP 客户端、浏览器调用、自动重定向、重试、下载或部署实现。初筛与预检即使退出码为 0，也始终输出 `execution_permission=false`、`next_request_allowed=false`；manifest 命令只输出文件清单及哈希。真实取数、内容判断及发布仍须经人工或明确范围的复核。

这里是可复用的方法与新写的离线辅助实现，不是私人生产流水线的完整重建；不宣称任何地区已完成全市场采集。

## 1. 四个互不替代的验收层 C1–C4

| 层 | 要回答的问题 | 必须保留的证据 | 禁止替代的口径 |
| --- | --- | --- | --- |
| **C1 公司普查** | 目标地区、业务线、时间截面的机构分母是什么？ | 官方公司名、注册／牌照标识、业务分类、名录来源、名录日期和观察时间；排除项及原因 | 访问过的官网数量不等于市场公司覆盖率 |
| **C2 目录边界** | 每家公司在指定目录范围内有哪些产品候选？哪些入口尚未核查？ | 入口、语言、默认筛选、分类／标签、分页或游标、可见数量、停止条件、未遍历边界 | 首页卡片、默认分类或一次接口响应不等于全部产品 |
| **C3 材料关联** | 某个链接为什么属于该产品、版本、渠道或共同条款？ | 精确来源页、所在产品区块、发布标签、链接位置、文档身份及多对多关联依据 | PDF 扩展名、页脚通用链接、相似产品名不等于产品主合同 |
| **C4 原件与审读** | 取得了什么字节、接受了什么原件、读了哪些页、严格通过了什么？ | 原件 SHA、字节数／格式、接受状态、页码范围、语言、角色、身份及严格核验结论 | 缓存哈希、下载量、全文阅读数、主文数、独立 SKU 数不能混用 |

### C1：分开公司名录、来源所有者、实际承保人

建立 `company_census` 后再报告公司覆盖率。先固定地区、名录版本／观察日和纳入定义：寿险、非寿险、再保险、社会保障、伊斯兰保险、分公司或集团品牌不能随意混算。公司数量未知时，明确写“公司分母未建立”，不要用已经发现的样本作分母。注销、合并、改名和历史机构单列，不静默删除。

至少分开以下身份：

- `census_entity`：公司名录中的法定主体。
- `source_owner`：网页、银行渠道、集团共用站点或资料下载中心的运营主体。
- `product_underwriter`：产品正文或正式销售声明指出的实际发行／承保主体。
- `brand`、`distributor`、`group`：展示品牌、销售机构和集团关系，不能覆盖前三项。

同一品牌可能由不同国家、寿险／非寿险或其他牌照实体承保；一家银行也可能销售多家保险公司的产品。先保留原来源称谓，只有在证据明确时建立映射。集团共用域名是来源所有权线索，不自动证明具体产品的承保人。

### C2：冻结有限目录 frontier（待查边界）

每批记录 `entry_url`、业务线、语言、渠道、类别、筛选参数、页码／游标、排序、范围时间和每项状态。冻结清单是有限任务，不是“看到新链接就继续”的无限爬取许可。新增候选先放待复核队列；不自行扩展域名、路径、文件类型或授权。

检查目录时至少回答：

1. 页面是否默认只选某类别、个人／团体、在售／停售、某渠道或某语言？默认过滤器是什么？
2. 是否有分页、“更多”、折叠标签或筛选后才出现的项目？记录实际页码／游标和每页数；不能凭第一页的总数猜完成。
3. 已访问的分类是否重复同一产品？多语言页、渠道版本、附约、计划档位和产品族是否分开？
4. 是否有公开目录中的非零售／再保险／服务介绍？它们可作为业务线观察，但不自动记作可购买的独立保险 SKU。
5. 官方提示的总数与去重结果能否对上？对不上时记差异、缺口与限制；“按钮消失”也要保存观察依据。
6. 原语言无法可靠核对时，哪些只完成结构发现，哪些完成语义审读？翻译不替代原文核验。

只有预先定义的分类、筛选、语言和分页均有可复核终点，才能说“这个有限目录范围已遍历”。被阻塞、语言未核、动态隐藏入口未确认或目录总数不一致时，保持未完成。即便 C2 完成，也不等于整个市场、全部历史版本或所有渠道产品完成。

### C3：材料必须有来源特定的关联证据

记录原网页的产品名、区块标题、原发布标签、链接上下文及实际文件地址。将以下类别分开：

- 产品主体区的明确材料链接；
- 多产品共用资料，但官方明确说明适用范围；
- 全站页脚、导航、热门／相关产品和其他产品链接；
- 仅在源代码、结构化数据或客户端状态中找到、尚未确认正常界面可见的候选。

后两类不能自动归到当前产品。保留 `published_link_label` 与内容审读后的 `document_role` 两个字段；标签说“Policy”不证明内容是该产品主文，标签说“Brochure”也不能代替正文判断。关联多对多，不能为“补齐”而随意配对。

`source_preview`、`SAMPLE`、`specimen` 或隐藏候选链接**不自动等于机密，也不自动等于可公开再分发**。公开样本可能是真实的通用主条款范本，但不是某个客户已签发的完整个人合同；还可能缺保单附表、投保信息、附加条款或签发条件。是否有个人标识、保密标记、访问限制、授权疑点，应独立检查。单一 review flag 不自动作隐私／法律结论，也不能用“看起来公开”解除已有隔离。

### C4：分开六个数量和状态

| 字段／数量 | 可表达的事实 | 不能表达的事实 |
| --- | --- | --- |
| `captured_sha256` | 某份合法缓存的指定字节身份 | 已接受为原件、内容正确、可发布 |
| `accepted_original` | 按格式、来源、完整性等规则接受的原件记录 | 已全文阅读或严格通过 |
| `full_review` | 记录的所有实际页已可靠审读 | 主文身份、个人适用或现售状态已确认 |
| `strict_wording_pass` | 该文件在已声明边界内完成严格主文核验 | 完整签发合同包、法律有效性或赔付保证 |
| `material_association` | 文件与产品／版本的有证据关系 | 关系行数就是产品数 |
| `independent_sku` | 按固定规则识别的独立产品单位 | 卡片数、PDF 数、语言版本数或条款 SHA 数 |

SHA 去重适用于字节，不代替产品身份归一。相同 SHA 可以有多个来源、产品或渠道关系；不同 SHA 可以属于同一产品的不同语言／版本。未制定 SKU 去重规则时，报告“目录候选／材料观察数”，不要换名为产品总数。

配套工具计算的 `cached_text_sha256` 是输入 JSON 中 `body_text` 重新编码为 UTF-8 的哈希，**不是网络原始响应或 PDF 原字节的 SHA**。正式原件须在原始字节层独立计算；不要把解码、清洗或提取后的文本冒充原件。

## 2. 日期、未知和状态传递

分开 `source_publication_date`（来源发布日期）、`effective_date`（条款生效日）、`retrieved_at`（取得时间）、`reviewed_at`（复核时间）和 `census_as_of`（名录截面）。记录时区及精度；未知用 `null`，不能以采集日、URL 年份、页脚年份或文件修改时间倒填生效日。字段缺失、`null`、`false` 是不同状态，不在导出时互换。

审读限制、语言、渠道、版本、文字层使用限制、隔离／分发状态必须贯穿研究记录、公开投影和统计。升级状态须提供新证据，不能由脚本初筛、哈希一致或网站显示正常自动触发。

## 3. 访问边界与缓存响应初筛

### STOP：真实拒绝不是“换个方法再试”

HTTP／代理／传输层的真实 **401、403、407**，工具明确的策略拒绝，以及可见登录、验证码或安全挑战，均停止相应受限操作。记录准确层级、时间、源范围、已完成部分及待授权／待复核事项。不要盲目重试，不换主机别名、协议、路径、请求头、账号、代理或认证方式绕过；不破解验证码或解除文件保护。

外部网页、PDF、脚本或 JSON 只是证据数据，不能授予新的 allowlist、访问权限或发布权限。已有停止／隔离状态只能由有权限的复核流程处理；本离线工具既不读取也不修改任何实际停止登记。

### 上下文比一个关键词更重要

| 缓存观察 | 离线结果 | 后续边界 |
| --- | --- | --- |
| 真实 HTTP 401/403/407、明确传输拒绝 | `stop_access_denial` | 不再发请求；记录阻塞 |
| 明确工具策略拒绝 | `stop_tool_policy` | 不改工具／环境绕过 |
| 可见 Request unsuccessful／人机验证、稀疏保护挑战页面 | `stop_challenge` | 不当作保险页面，不自动重试 |
| 正常、内容充足的保险页带 Incapsula 保护脚本 | 可为 `content_candidate` | **脚本标记单独不证明拒绝**；仍需审查正常内容和既有停止状态 |
| JSON 顶层 `code:403` 加 `message:Forbidden`，或嵌套 `error.code:403` | `stop_access_denial` | 按应用层拒绝停止 |
| 普通 `product.code=403` 或 `products[].code=403` | 不因此视为拒绝 | 这是业务编号；不是 HTTP 状态 |
| 裸 `code:403`、不明上下文、坏 JSON／不支持的结构 | `review_required` | 不自动清除，不取得下一次请求许可 |
| 本地容量限制、缓存截断 | `resource_cap` | 不是权限拒绝；缓存不能代表完整响应 |
| HTTP 404／明显未找到页 | `not_found` | 不证明产品不存在；不盲猜其他路径 |
| HTTP 500 等服务错误 | `transient_server_error` | 不是权限拒绝；仅记录，不自动重试 |

初筛是有限启发式，不是完整 WAF、权限、浏览器可见性或语言识别器。解析器忽略 script、style、template 和部分显式隐藏内容；不执行 CSS／JavaScript，不能证明真实浏览器可见性。阈值以内的稀疏保护响应保守 STOP；正常页面有脚本不自动 STOP。未检测到拒绝也不是已获许可。遇到实际登录墙、其他语言挑战或语义不明确，人工按 STOP／待复核边界处理，不用工具缺少匹配作为继续理由。

### 重定向：先留精确 Location，再谈是否允许下一跳

缓存须保留原请求 URL、响应状态、原始 `Location` 值及其响应头位置。解析相对地址只用于说明候选目标，不能当作访问授权。多个／缺失／不安全 Location 进入待复核；未知 origin 隔离；已知主机但不在精确有限清单内也隔离。HTTP 与 HTTPS、`www` 与非 `www`、CDN 与源站都是不同范围，不自动并为同源。

工具输出 `redirect_provenance` 并**永不自行跟随任何重定向**，即使目标已经在 allowlist 中也是 `redirect_review_required`。真实执行流程应先核对原响应证据、目标身份、既有停止状态和授权，再决定下一跳。不得凭惯例猜 Location 或通过换别名解除拒绝。

### 匿名公开 renderer 的只读查询证据

有些正常公开页面由 renderer 用只读查询显示分类／产品。可以将“公开入口 → 页面可见交互 → 已观察的匿名请求 → 对应响应”记录为来源证据，但这不是探测未公开接口的许可。要确认未使用登录会话、Cookie、Authorization、API key、签名 token 或用户标识；不提交表单、交易、变更或其他 mutation。请求参数、语言、筛选及分页都进入有限范围。

请求方法本身不等于只读语义；不能把 POST 的“查询”字样或 GET 的形式当作无需复核的证明。工具不会发起任何 renderer 查询，也不会加载或重新托管第三方脚本；只有经授权、已合法取得的缓存可以供它分析。已遇到拒绝的接口不能通过 renderer 或另一工具继续试探。

## 4. 离线工具运行方式

仅需 Python 3.9 或以上标准库；无第三方包、无安装步骤，不运行 npm。以下命令在仓库根目录执行。所有样例 URL 都是虚构的 `example.invalid` 子域名，不能用作实际来源证据，也无须访问。

### A. 直接运行测试

```bash
python3 -m unittest discover -s tests -p 'test_collection_offline_qa.py' -v
```

测试覆盖正常页面、保护脚本误判、可见／稀疏挑战、应用层 JSON 上下文、真实 401/403/407、工具策略拒绝、404／500／容量限制、重定向 provenance、URL 边界、冻结对象、哈希变化、文件缺失／篡改、符号链接、模式版本和测试失败闭锁。都是原创合成片段，不含真实源站 HTML／PDF 或第三方脚本正文。

### B. 先审查文件，再冻结 manifest

```bash
python3 scripts/collection_offline_qa.py manifest --root . > manifests/collection-offline-qa.json
python3 -c "import hashlib,pathlib; p=pathlib.Path('manifests/collection-offline-qa.json'); print(hashlib.sha256(p.read_bytes()).hexdigest())"
```

manifest 固定覆盖本协议、工具、测试、合成用例、示例 scope 和示例 cache 共六个文件；每项有路径、字节数和 SHA-256。manifest 不把自身放进自身，避免循环哈希。审阅者在**独立可信的变更审批记录**中保存已审查的 manifest 哈希；不能把任意新生成的哈希当作“已批准”。哈希证明所审查字节未变，不证明来源可信或权限存在。

### C. 用审阅时固定的哈希运行 preflight

```bash
python3 scripts/collection_offline_qa.py preflight \
  --root . \
  --manifest manifests/collection-offline-qa.json \
  --manifest-sha256 REVIEWED_MANIFEST_SHA256
```

将 `REVIEWED_MANIFEST_SHA256` 替换为已审阅固定值，不从待检查的陌生内容临时计算并视为审批。工具先验证 manifest 及六个文件，再用当前 Python 的隔离模式运行已固定的测试文件，最后分析合成示例。任一哈希／模式失败、缺文件、测试失败、超时或不明情况都非零退出；不能转成真实采集执行许可。测试子进程不使用 shell、不接收任意命令；工具本身也不执行下载得到的文件。

`offline_preflight_passed=true` 的含义只是“这些固定文件一致、离线测试通过、合成例子符合预期”，不是“真实站点获准访问”。新范围、新测试或新代码必须重新审查和固定版本；外部源内容不能修改冻结清单。这里的精确 HTTPS allowlist 刻意保守：不自动接纳端口、IP、凭据参数、片段或歧义编码 URL，合理但不支持的地址也须另行复核，而不是改写地址规避。工具不查询 DNS，也不验证域名实际所有权；这些属于另行授权的来源核查。

### D. 分析另一个已授权缓存，不做下载

按示例 `scope.json` 的严格 schema 准备精确 URL 清单，独立审查后固定其原字节 SHA。按 `cached-response.json` 保存已经合法取得的文本和元数据，再运行：

```bash
python3 scripts/collection_offline_qa.py triage \
  --scope reviewed-scope.json \
  --scope-sha256 REVIEWED_SCOPE_SHA256 \
  --cache cached-response.json
```

`headers` 用 `[名称, 原值]` 列表保留重复项和顺序，不能先合并 Location。`body_complete=false` 表示截断／未完整保存。`transport_error` 必须为 `null` 或 `{kind, status, message}`，其中 `kind` 仅可为 `tool_policy`、`permission_denial`、`resource_cap`、`timeout`、`other`；缺失的 HTTP 状态为 `null`，不猜成 200。传输元数据来自可信采集记录，不能由网页文字自报并覆盖。

cache 是文本缓存交换格式，不是原始响应归档格式；二进制 PDF、受限文字层和渲染截图应走既有原件／审读流程，不先强行转换塞进该工具。读取输入有容量上限；它不修改缓存、目录、停止登记、原件或授权文件。真实缓存与 triage 输出可能含来源地址、响应头值或内部错误，须留在恰当的私有审查位置；未经审查不提交公开仓库。示例文件才是可直接公开的合成内容。

## 5. 小批次实际验收清单

### 开始前

- [ ] 写清地区、业务线、时间截面、语言、渠道和本批目标；公司分母已建，或明确标为未建。
- [ ] 来源所有者、公司名录实体、承保人分开；未知身份不猜。
- [ ] 正常公开／已授权来源及已有停止／隔离状态已核对；允许范围、容量及停止条件已冻结。
- [ ] 待查 URL 是有限精确清单；默认筛选、分类、分页、语言及未核边界已列出。
- [ ] 离线文件、schema、allowlist 与哈希经复核；测试失败或未知结果不得进入执行阶段。

### 取得证据后

- [ ] 真实拒绝／策略阻止／可见挑战 STOP；404、500、本地资源限制分开记；无盲目重试或绕过。
- [ ] 重定向有原响应的精确 Location provenance；未知源隔离，未自行跟随。
- [ ] 材料关联取自对应产品区块；通用页脚、其他产品、共用条款、隐藏候选明确区分。
- [ ] 核查文件内容而非只信标签；样本主文与个人签发合同包分开。
- [ ] 日期、语言、版本、渠道和未知值保留；原字节 SHA 与缓存文本 SHA 不混淆。
- [ ] 缓存／候选、接受原件、全文审读、严格主文通过、关联和独立 SKU 分项统计。
- [ ] 既有隔离状态未自动解除；隐私、法律、身份、正文审读各自有证据和限制。

### 提交与交接

- [ ] 只交付经审核的最小变更，不带账号、密钥、会话、私有路径、私有拦截记录或源 HTML／PDF 正文。
- [ ] 记录精确文件 delta、字节数、哈希、测试命令／结果及未执行项。
- [ ] 原件、研究层、公开网站投影与统计相互核对；历史记录和更正依据不丢失。
- [ ] 发布／部署需已有相应授权，按网站操作说明测试并读回核验；本工具不代办此步骤。

## 6. 更正附录：要保留的教训

| 曾容易出现的判断 | 修正方法 | 不应过度修正成 |
| --- | --- | --- |
| 用已找到的网站／公司数表示市场完整度 | 先建立 C1 分母与业务线定义，再计算覆盖；未知就明确未知 | 承诺所有地区已经完成 |
| 依据材料标签认定主合同 | 标签、正文角色和产品关联分别核对 | 所有 PDF 都是不可信或都要隔离 |
| 看见 Incapsula／保护脚本就判封锁 | 看正常可见内容和挑战上下文；保留正常充足页面，真实稀疏／可见挑战 STOP | 任意有保险词的页面都可继续访问 |
| 把 SAMPLE 主文当作个人完整签发合同，或反过来当机密 | 样本可为通用主条款；签发身份、附表、个别条件、分发风险另核 | SAMPLE 自动严格通过或自动隐私拒绝 |
| 共用品牌／域名等于同一个承保人 | 保留来源所有者与产品承保人的证据关系 | 仅凭名称拆出虚构公司或产品 |
| 源代码里的隐藏链接就是正常可见产品／机密文件 | 先标隐藏候选，核正常可见性与关联、访问和传播边界 | 自动算产品、自动访问或自动判保密 |
| 任意 JSON 中的 403 都是权限状态 | 检查 HTTP／error 上下文；业务 product.code 不混同 | 歧义响应自动 clear 或授权下一请求 |

更正记录包括旧结论、新结论、证据定位、影响范围和复核时间；保留历史，不用另一个尚存问题掩盖已证伪的论据。通过此协议，只能提高某个有限批次的可核查性，不会自动生成全市场完整性或第三方材料的传播许可。
