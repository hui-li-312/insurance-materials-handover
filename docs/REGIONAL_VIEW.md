## 初版固定输入与确定性方法

- 输入基线：GitHub 已验证提交 `58fb5d5c5ab09e74c4f3be88d2c9fa1d7b8f144b` 的 313 文件公开交接仓库；在已验证的 264 文件基线上加入第四批 49 个新元数据文件，并替换 LATEST／README。具体源文件字节数及哈希固定在批准输入清单。
- `website/config/coverage-approved-inputs.json` 固定该基线的公开 `coverage/` 文件字节数与 SHA-256；不是整个工作区的自动扫描入口。
- `scripts/coverage.mjs` 只列举并读取 `coverage/LATEST.json` 中 20 个已支持 active feeds 的具体文件。每次读取先核对批准清单；输入改变、未知 feed、父记录缺失或替换数量不符即失败。
- 输出是 `public/coverage-observations.json` 小索引与 12 个按地区切分的 JSON。没有产品观察的地区仍保留地区项和空数组，前端明确显示尚未发布，不伪称市场有 0 个产品。
- 无网络请求、运行时密钥、第三方依赖、动态采集、模糊匹配或通用猜测 schema。相同输入逐字节生成相同输出。源文件路径、行号、feed 和输入哈希保留可追溯性。
- 公开材料链接只接受无用户凭据的 HTTP(S)。源 `null` 保持 `null`，无效 blob 引用不变成可点击 URL。不会从文件名或镜像推测下载地址。

## 字段与展示原则

`observations[]` 的 `kind` 是来源观察类型；`legalIssuer` 是来源中明确的归属，缺失时为 null；`issuer` 可为共享品牌加待核标识。`sourceId`、`provenance` 不作为独立 SKU 证明。`facts` 保留明确的来源限定字段；目录分类、附加险、系列、组件、历史版本不被隐藏。

`materials[]` 的 `kind` 保留完整来源分类，`materialRole` 单独保留角色，`specimen` 为 true 或 null（未知），`sourceStatus` 保留来源抓取状态，`formalOriginalCredit` 固定为 0；发布日、生效日、文件语言分别处理。源抓取、角色判断、全文审查、版权许可和完整合同是不同维度。

**样本／SAMPLE 不是宣传册分类。** 样本仍可能是真正的主条款／总保单文本；本投影已将 specimen 标识与 material role、完整性、审查状态分开建模。PH 样本材料保留真实总保单条款角色；China Life 保留条款类型与仅首页核验界限。不会据未批准材料升级，也不把“非个人已签发保单”误写成“主条款不存在”。

## 本地启动与复现

```bash
cd website
npm ci --ignore-scripts --offline
npm run coverage:check
npm run coverage:import
npm test
npm run build
npm start
# http://127.0.0.1:8080/coverage.html
```

需要 Node.js 24，以及完整仓库的 `coverage/` 与 `website/` 相对结构。`coverage:import` 只重建补采 JSON，不触碰旧 `product-library.json`。`coverage:check` 和 `build` 校验输入及现有输出，不接受静默漂移。静态托管只发 `dist/`；不要上传原件或整个仓库。部署、权限与回滚操作沿用 [WEBSITE_OPERATIONS.md](WEBSITE_OPERATIONS.md)。
